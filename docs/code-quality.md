How code quality is checked in LinkUp, and what has been found and fixed. Updated each sprint.

## Tooling overview

| Check                    | Tool                                                  | When                               |
| ------------------------ | ----------------------------------------------------- | ---------------------------------- |
| Static analysis          | SonarQube Cloud (C#, TypeScript, YAML, Docker, …)     | Every PR and every push to `main`  |
| App tests + coverage     | Jest (`jest-expo`) + React Native Testing Library     | CI, and `npm test` locally         |

## SonarQube setup

### Why SonarQube Cloud

Considered: self-hosting SonarQube Community Edition on our Dokploy VPS vs. SonarQube Cloud.

Chose **SonarQube Cloud** because the repository is public (free plan), there is no server to maintain, and it analyses pull requests and reports the result as a PR check. Community Edition only analyses the main branch and would use 2–4 GB RAM on the VPS.

### Analysis pipeline

A single GitHub Actions job analyses the whole monorepo:

1. Run app tests with coverage → `app/coverage/lcov.info`
2. `dotnet sonarscanner begin` — SonarScanner for .NET, pinned in `backend/dotnet-tools.json`
3. Build the backend (C# is analysed during the build)
4. Run backend tests with coverage → `coverage.opencover.xml`
5. `dotnet sonarscanner end` — uploads C# results plus all other files

**Decision — one scanner for both languages.** The first setup used the generic SonarScanner with a `sonar-project.properties` file. It analysed only the TypeScript app: the generic scanner can't analyse C#, so the backend, where most Sprint 1 logic lives, was invisible. SonarScanner for .NET analyses C#, and its multi-language mode (`sonar.scanner.scanAll`, on by default) also analyses the TypeScript, YAML and Docker files in the repository. This keeps one SonarQube project and one quality gate for the whole product. The alternative, two SonarQube projects (one per language), would split the results and need two tokens and two gates.

### Exclusions

| Setting                     | Paths                                                                   | Reason                                                                                                                   |
| --------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `sonar.exclusions`          | `node_modules`, `bin`, `obj`, `app/coverage`, `app/.expo`, `app/assets` | Dependencies, build output and generated files                                                                           |
|                             | `backend/.../Data/Migrations`                                           | Generated by EF Core                                                                                                     |
| `sonar.coverage.exclusions` | `app/src/app/**` (route screens), `app/src/constants/**`                | Screens are placeholders/layout in Sprint 1; logic lives in tested modules (`api/`, `storage/`, `hooks/`, `components/`) |
|                             | tests, config files                                                     | Not production code                                                                                                      |

### Quality gate

Default **Sonar way** gate, applied to new code: no new bugs, vulnerabilities or code smells above rating A, **≥ 80 % coverage**, ≤ 3 % duplication, all security hotspots reviewed.

### Testing

| Suite   | Tests | What is covered                                                                                                                                                                                                                    |
| ------- | ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
